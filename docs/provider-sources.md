## Reflection probe and mob rendering (checked 2026-10-24)

`/sift doctor` reflects the optional methods used by the current bridge and reports found/missing signatures for enabled Nexo, ItemsAdder, and Oraxen installations. Nexo's documented generic block test is `NexoBlocks.isCustomBlock(Block)`; the API docs do not list `isNexoBlock(Block)`, so the bridge now uses the documented method instead. ItemsAdder documents `CustomBlock.isInRegistry(String)`, `byAlreadyPlaced(Block)`, and `place(String, Location)`; Oraxen documents `OraxenItems.getIdByItem(ItemStack)`, `OraxenBlocks.getBlockIDs()` and `isOraxenBlock(Block)`. A found method proves only the Java signature exists; it does not prove that provider YAML parsed, a configured content ID resolves, or the block/item works in game. Missing signatures produce a one-time warning at startup and are repeated in doctor output.

Official mob references: [MythicMobs mob configuration](https://wiki.mythiccraft.io/mythicmobs/Mobs/Mobs) defines mobs using a base entity `Type`; [ModelEngine's MythicMobs integration](https://wiki.mythiccraft.io/modelengine/MythicMobs) exposes its mechanics to MythicMobs configs, and [ModelEngine's model mechanic](https://wiki.mythiccraft.io/modelengine/Skills/Mechanics/Model) attaches a model ID to a target entity. [ItemsAdder Java API examples](https://github.com/ItemsAdder/wiki/blob/main/developers/java-api/examples.mdx) show `CustomEntity.spawn(id, location)` and distinguish an unresolved custom-entity ID. Current generated MythicMobs definitions do not attach a model and therefore must not be described as custom-rendered mobs. No third-party JAR or asset was downloaded or unpacked for this check.

Paper's 26.3 Javadocs document [piston extend moved-block lists](https://jd.papermc.io/paper/26.3/org/bukkit/event/block/BlockPistonExtendEvent.html), [piston retract moved-block lists](https://jd.papermc.io/paper/26.3/org/bukkit/event/block/BlockPistonRetractEvent.html), and [the operation direction](https://jd.papermc.io/paper/26.3/org/bukkit/event/block/BlockPistonEvent.html). They do not explicitly specify the coordinate displacement for a retracting moved block. The implementation uses the opposite of the reported operation direction for retract; verify this on a Paper 26.3 server before marking piston transfer live-checked.

**Evidence limitation:** ItemsAdder, MythicMobs, ModelEngine, Geyser-Spigot, ViaVersion, ViaBackwards, and ViaRewind do not all publish Bukkit `plugin.yml` files in a public source repository. Their canonical keys were matched to official product/API documentation and official platform artifacts where public. `/sift doctor` reports the actual installed plugin name/version so a server can expose a renamed or platform-specific installation.
